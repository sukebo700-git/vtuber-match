# 文字起こし精度ベンチマーク用 読み上げ台本

## 使い方

1. この台本を **普通の話速で読み上げて録音する**（3分弱）
2. 録音条件を変えて**3本**録る
   - `A1-clean` … BGMなし・マイクのみ
   - `A2-bgm` … 配信用BGMを流しながら
   - `A3-game` … BGM＋ゲーム音を流しながら
3. 下の「正解テキスト」と文字起こし結果を突き合わせてCER（文字誤り率）を出す

**この方法の要点**: 正解が先に確定しているので、手で書き起こす作業（3分あたり30〜60分）が要らない。
拾ってきた配信では精度を測れない。

## 録音方法

**精度測定に映像は不要。音声だけあればいい。** ツールは音声ファイル（m4a / wav / mp3 / mp4）を
そのまま受け付ける。配信用のOBS設定を触る必要はない。

### 手順（このPCにはマイクが繋がっていないため、スマホで録る）

1. **スマホのボイスメモで台本を読み上げる**（3分弱・1回だけでよい）
   - iPhone …「ボイスメモ」アプリ
   - Android …「レコーダー」アプリ
   - 静かな部屋で、口から20〜30cm離して普通の話速で
2. **PCに転送する**（メール添付 / Googleドライブ / USBケーブル / LINEのKeep など）
3. `work/bench/voice.m4a` などに置く

**BGM・ゲーム音は後から `mixbgm.py` で混ぜる。** スピーカーで流しながら録るより良い:

| | 流しながら録る | 後から混ぜる |
|---|---|---|
| SNR（声とノイズの音量比） | 制御できない | **dB単位で指定できる** |
| 再現性 | 録るたび変わる | **同じ声から何度でも作れる** |
| 段階的な検証 | 不可 | **SNRを振って一気に作れる** |
| 読み上げ回数 | 3回 | **1回** |

### ノイズ源を用意する

配信で使っているBGMのファイル、またはゲーム実況の録画から抽出する。

```bash
# 動画からゲーム音・BGMを抜き出す
python mixbgm.py --extract-noise "配信.mp4" --out work/bench/game-noise.wav --start 200 --dur 180
```

### SNRを振って素材を作る

```bash
python mixbgm.py --voice work/bench/voice.m4a --noise work/bench/game-noise.wav                  --sweep 20,15,10,5 --outdir work/bench
```

`snr20.wav` / `snr15.wav` / `snr10.wav` / `snr05.wav` が出力される。

| SNR | 相当する状況 |
|---|---|
| 20dB | BGMが小さめ。実況の標準的な設定 |
| 15dB | 一般的な配信のBGM音量 |
| 10dB | BGMがかなり大きい。ゲーム音が乗っている状態 |
| 5dB | 声とノイズがほぼ同じ。かなり厳しい条件 |

## 測り方

```bash
# クリーン
python asrtest.py --in work/bench/voice.m4a --start 0 --dur 180 --model large-v3 --device cuda

# ノイズあり
python asrtest.py --in work/bench/snr10.wav --start 0 --dur 180 --model large-v3 --device cuda
```

出力された文字起こしを、下の「突き合わせ用の正解テキスト」と比較してCERを出す。

## マイクを繋ぐ場合（本番運用するなら）

このPCで直接録りたい場合、認識されている入力デバイスは
`マイク (Steam Streaming Microphone)`（Steamの仮想デバイス）のみ。
USBマイクかヘッドセットを接続すれば、以下で直接録音できる。

```bash
# 接続後、デバイス名を確認
ffmpeg -list_devices true -f dshow -i dummy

# 録音（180秒）
ffmpeg -f dshow -i audio="デバイス名" -t 180 -ac 1 -ar 48000 work/bench/voice.wav
```

### OBSを使う場合（Lo-Fi配信の設定を壊さない手順）

**新しいプロファイルを作って切り替える。** プロファイルは出力・音声・映像の設定を
丸ごと分離するので、Lo-Fi用の設定には一切影響しない。

```
プロファイル → 新規 → 「benchmark」など名前をつける
（この新プロファイル内で録画設定を変更する。Lo-Fi用プロファイルは無傷）
録り終わったら プロファイル → Lo-Fi用 に戻す
```

**配信中は触らないこと。** OBSは配信・録画中のプロファイル切り替えを禁止している。

### マルチトラック録画（素材Cのみ・後回しでよい）

コラボの話者色分けの検証にだけ必要。**精度測定には不要。**

```
設定 → 出力 → 出力モード:「詳細」
  録画タブ  録画フォーマット: MKV / 音声トラック: 1 と 2 にチェック
  音声タブ  トラック1: マイク / トラック2: デスクトップ音声
設定 → 音声 → 詳細
  マイク → トラック1のみON / デスクトップ音声 → トラック2のみON
```

```bash
python clip.py probe --in A3-game.mkv     # 「音声トラック: 2 本」と出れば成功
```

## 何を測るか

| 項目 | 見どころ |
|---|---|
| **固有名詞** | モンハンワイルズ / ゼンゼロ / エペ / スト6 / にじさんじ / ホロライブ / ぶいすぽ |
| **人名（造語・英数混じり）** | ナーロン / ミゼリィ / たろう2000 / XxKotaroxX / しゃけ弁当 |
| **ネットスラング** | 草 / てぇてぇ / 同接 / スパチャ / ガチ恋距離 / しんど / えぐい |
| **叫び声** | 「うわあああああ！」が拾えるか、無音扱いされないか |
| **笑い** | 「あははははっ」が幻覚（無関係な文）を誘発しないか |
| **早口** | 一息の長文で脱落が起きないか |
| **小声・語尾消え** | 「……まあ、いいか」が拾えるか |
| **数字表記** | 「十二月三十一日」か「12月31日」か、表記が安定するか |
| **BGM耐性** | A1 / A2 / A3 でCERがどれだけ悪化するか |
| **単語タイムスタンプのズレ** | 実際の発話位置と字幕表示のズレ（目視） |

## 固有名詞辞書の効果も測る

`--dict` を付けた場合と付けない場合で比較する。

```bash
# 辞書なし
python clip.py subs --in A2-bgm.mkv --start 0 --end 2:30 --work work/nodict

# 辞書あり
python clip.py subs --in A2-bgm.mkv --start 0 --end 2:30 --work work/dict --dict assets/terms-sample.txt
```
